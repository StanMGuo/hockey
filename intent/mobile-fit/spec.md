# Spec: 适配手机端

Paired intent: `intent.md` (accepted). Status: accepted.

## 1. Problem restatement

手机是主要使用场景，用户是低龄小朋友。短竖屏上冰场约占 60% 高度，底部按钮盖住 D2 说明。本变更只调整布局：竖屏让出完整说明区、尽量不滚动，竖屏弹层贴底，横屏保持左右布局。规则、关卡、流程、进度不变。

## 2. Requirements

### 2.1 Functional

| ID | Requirement |
| --- | --- |
| F1 | 竖屏对局：D1、D2 的标题和说明全文可见，底部操作按钮不覆盖任何说明或总评。 |
| F2 | 竖屏对局尽量不出现页面滚动或面板内部滚动。空间不够时，先把冰场缩到大约视口高度的一半，再收紧间距；不靠滚动把说明藏起来。 |
| F3 | 冰场在竖屏仍完整可见（含本方球门方向），可拖拽 D1 / D2。守门员热区在验收视口上不小于约 44×44 CSS 像素。 |
| F4 | 横屏对局保持冰场在左、说明在右。验收横屏 844×390 上，两行说明和操作按钮同时可见，冰场不被面板挤到无法辨认站位。 |
| F5 | 竖屏弹层改为贴底弹出，覆盖 How to play、Settings、Practice 选择、Game Challenge 选择与锁定提示。主按钮在弹层内可见，点遮罩可关闭（与现在点 `#sheet` 背景关闭一致）。 |
| F6 | 横屏与宽屏弹层仍为居中卡片。 |
| F7 | 首页在验收竖屏上一次看全：三个模式按钮、How to play、Settings。不靠滚动才能点到。 |
| F8 | 密码门在验收竖屏上，键盘未弹出时，密码框和 Unlock 同时可见。 |
| F9 | Learn / Practice / Game 的进入、检查、解锁、文案含义、音效开关、进度存储保持现状。 |
| F10 | 安全区（刘海、底部横条）继续避让，按钮不落在 `safe-area-inset` 里面。 |

### 2.2 Non-functional

| ID | Requirement |
| --- | --- |
| N1 | 不改 `kindOf`、`zonesFor`、`evaluate` 及关卡数据。 |
| N2 | 不新增依赖，不改成原生 App。 |
| N3 | 配色、字体、按钮文案含义保持；只改布局、间距、弹层位置和必要的壳结构。 |
| N4 | 操作目标保持适合儿童：可见按钮高度不低于 44px。不为了塞进屏幕把主按钮缩到这个值以下。 |
| N5 | `npm test` 保持通过。本变更不要求新的规则引擎测试。 |
| N6 | 完成前用浏览器在 §2.3 三个视口核对 §3.4 的 MANUAL 清单。 |

### 2.3 Acceptance viewports

| 视口 | CSS 像素 | 方向 |
| --- | --- | --- |
| iPhone SE | 375×667 | 竖屏 |
| iPhone 15 | 393×852 | 竖屏 |
| 手机横屏 | 844×390 | 横屏 |

桌面宽屏不是本次主场景，但现有横屏左右布局不得被手机规则改坏。抽查宽度 ≥ 1024px 的横屏：冰场与面板仍并排。

### 2.4 Non-goals

新关卡、新模式、新音效、平板专用信息架构、多语言、安装引导重做、改规则数值。

## 3. Design

### 3.1 Layout

竖屏 `#play` 为上下结构。

- 冰场 `#rinkWrap` 高度取「按冰场比例能放下的高度」和「视口减去说明区所需高度」的较小值。说明区所需高度按头部、比分条、提问、两行 D 说明、总评、操作按钮都不折叠来估算。
- 在 iPhone SE 上，这个结果大约是视口高度的一半。允许略低于一半，前提是说明区完整且不滚动。
- 在 iPhone 15 上，说明区用不完下半屏时，多出来的高度给冰场，不把冰场锁死在 50%。
- `#actions` 不再用 sticky 盖住内容。它固定在面板底部，说明在它上方自然排开。面板内容超出时，优先缩小冰场和间距，而不是打开滚动。

横屏 `#play` 维持左右分栏。仅当高度不够放下两行说明时收紧面板间距，仍不引入滚动作为主要交互。

竖屏 `#sheet` 对齐到底部，卡片顶角圆角、底角贴边，宽度 100%，底部留出安全区。横屏不套用这套对齐。

首页和密码门在验收竖屏用收紧间距来放进一屏。只有内容仍然高于视口时，才允许该屏自身滚动；验收机型的目标是不发生。

### 3.2 Files

| Path | Change |
| --- | --- |
| `src/screens/GameApp.tsx` | 仅当现有 DOM 无法把操作区与说明区分开时，加一层面板内容容器。不改模式按钮的 id。 |
| `src/styles/app.css` | 竖屏高度分配、取消 sticky 遮挡、短屏间距、竖屏底栏弹层、首页/密码门一屏放下。 |
| `index.html` | 仅当需要键盘弹出时缩小布局视口，才补 viewport 标记。 |
| `src/screens/gameController.ts` | 不改流程。弹层 HTML 由现有 `openSheet` 生成，样式负责贴底。 |

不改 `src/engine/`、`src/data/`、`src/state/`。

### 3.3 Behavior that must stay

- 竖屏冰场仍用现有 `portraitViewBox` 与 `rotate(-90)`，本方球门在下方。
- 拖拽仍走现有 pointer 事件与 `toRink`。
- 弹层开关仍走 `openSheet` / `closeSheet`，点背景关闭。

### 3.4 Test strategy

`AUTO`：`npm test` 全绿。不新增引擎用例。

`MANUAL`：每个验收视口都看实际画面，不只看截图是否「看起来整齐」。

| ID | 视口 | 检查 |
| --- | --- | --- |
| T-UI-01 | SE、iPhone 15 竖屏 | 首页三个模式按钮和两个小按钮都在视口内，页面没有滚动条 |
| T-UI-02 | SE、iPhone 15 竖屏 | Learn 开局：D1 与 D2 说明全文可见，操作按钮不重叠它们，面板不滚动 |
| T-UI-03 | SE 竖屏 | 拖动 D1 一次，球员跟着手指移动，松手后仍在冰面上 |
| T-UI-04 | SE、iPhone 15 竖屏 | How to play、Settings 从底部升起；主按钮可见；点遮罩关闭 |
| T-UI-05 | 844×390 | 冰场在左、面板在右；两行说明和按钮同时可见；弹层仍居中 |
| T-UI-06 | 宽度 ≥ 1024 的横屏 | 左右布局仍在，没有变成手机底栏 |
| T-UI-07 | SE 竖屏 | 密码门在键盘未弹出时，输入框和 Unlock 都在视口内 |

Done（G4）需要 T-UI-01…07 有浏览器核对记录，并且 `npm test` 通过。没有这两组证据不算完成。

## 4. Areas of concern

| Concern | Mitigation |
| --- | --- |
| SE 上未压缩的说明区大约 345px，半屏大约 333px，差一截 | 先收紧间距和字号，主按钮保持 ≥ 44px。仍不够时冰场略低于一半。禁止用滚动补这截差 |
| How to play 文案在 SE 上可能高于一屏 | 弹层最高到视口扣除安全区。验收时若仍放不下，只允许弹层内部滚动，并在实现记录里写明；页面本身不滚动 |
| 冰场变小后拖拽热区变小 | 验收 T-UI-03。若低于约 44px，只加大透明热区，不改站位规则 |
| 系统键盘盖住密码框 | 验收范围是键盘未弹出（T-UI-07）。键盘弹出后的挤压不作为本次失败条件，除非实现时顺手能让输入框留在可见区 |
| 桌面被手机媒体查询误伤 | T-UI-06。竖屏底栏规则必须同时满足竖屏，不能只看窄宽度 |

## 5. Open questions

无。未决项不阻塞本 spec。键盘弹出后的密码门体验明确不纳入本次失败条件（见 §4）。
