# Intent: 按球员身份记住进度

Author: Stan Guo. Status: accepted.

## Problem

球员和教练每次重新打开 Hockey Defence Trainer，都要再输入一次写死的准入密码。关掉标签页、关掉浏览器或从主屏幕重新打开 PWA 都会再问一次。

另外，重新进入之后进度从零开始。使用者要的是自己的进度：用球员身份认出来之后，接着自己的记录玩。

已核对代码（未改实现）：

- 密码门把「已解锁」写在 `sessionStorage` 的 `hdt-gate-ok`。会话结束就消失，所以每次新开都会再要密码。密码仍是写死的 `hawksu9red`，而且写在前端源码里。
- 关卡进度写在这台浏览器的 `localStorage`（`hdt-progress-v1`），整台设备一份，没有球员档案，也没有数据库。
- 现有工程没有后端。要「到数据库里查这个人在不在」，必须新增服务端和数据库。

## Proposed outcome

1. 进来同时输入 nickname（或 first name）、球衣号和短密码。名字加球衣号是一份 profile 的唯一身份。球衣号可以重复，名字不同就是另一个人。
2. 名字、球衣号、短密码三者与已有档案一致：不再要团队密码，进入这个人的进度。只知道名字和球衣号不够。对不上、库里没有这个名字、或没有这个球衣号：不能进入已有档案，改走团队密码。
3. 团队密码通过之后，用刚才这一对名字和球衣号新建 profile，并设定短密码。团队密码只用于新建档案。
4. 这台手机上已有的匿名进度：让使用者输入名字和球衣号。这一对还不存在时，建成 profile，把本机进度放进该 profile。这一对已经存在时，进入已有档案，保留云端进度，不用本机匿名进度覆盖。
5. 规则数值、关卡内容、Learn / Practice / Game 流程不变。
6. 本变更按 AI-Native SDLC 走完 `intent.md` → `spec.md` → `plan.md`，计划被接受后再改代码。

同一对名字和球衣号在另一台设备上打开同一份进度。排行榜不是本需求。服务端放在哪里本阶段不决定，因此本 intent 接受后也先不进入实现。

## Affected users and systems

- **用户**：Hawks U9 的球员。一台设备上可能先后进入不同球员。
- **系统**：现有密码门和 `src/state/` 之外，以后需要数据库，以及只在服务端核对团队密码和短密码的接口。前端不能再保存能单独放行的团队密码。
- **验证**：一对身份加短密码建档、同号不同名再建一份、三者一致才进入、对不上时要团队密码、匿名进度只在新建时并入。服务端未定之前不实现。

## Constraints

- 不改 `kindOf` / `zonesFor` / `evaluate` 的语义和数值。
- 不改 Learn / Practice / Game 的玩法流程和解锁条件（仍是前一档累计 5 次合格）。
- 团队密码只在服务端验证。不能继续只放在前端代码里。
- 写实现代码之前，必须有被接受的 `spec.md` 和 `plan.md`。服务端位置未定，不得开工实现。
- 未获明确要求，不 commit、不推送。

## Non-goals

- 排行榜
- 邮箱、短信或第三方账号登录
- 本阶段选定或搭建服务器
- 修改关卡、文案含义或视觉品牌

## Decisions（已随本 intent 接受）

1. 进入时必须同时输入 nickname 和 jersey number。对不上、库里没有这个名字、或没有这个球衣号，都不能进入已有档案，要改输写死的团队密码。
2. 同一个球衣号可以有多份档案。唯一身份是 first name（或 nickname）加球衣号这一对。
3. 回来的人每次都要输入短密码。名字、球衣号、短密码三者一致才进入。只知道名字和球衣号的队友不能进入。
4. 这台手机上已有的匿名 `hdt-progress-v1`：使用者再输入名字和球衣号。这一对还不存在时创建 profile，并把本机进度放进去。这一对已经存在时进入已有档案，保留云端进度，不用本机匿名进度覆盖。
5. 服务端放在哪里暂时不考虑，不在本 intent 里选型。

## 仍然成立的边界

名字加球衣号是档案名字，不是两道密码。队里看得到这两项。短密码才是只有这个孩子知道的秘密。

谁先用团队密码建下一对名字和球衣号，谁就占住这一对。打错一个字母会建成另一份 profile，进度不跟过去。

团队密码现在写在前端源码里。服务端还没定，这段流程还不能安全地做出来。
